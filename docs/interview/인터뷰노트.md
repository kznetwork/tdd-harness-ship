# 인터뷰 노트 — 배송비 계산 (맘 테스트)

- 인터뷰 대상: 홍길동 (온라인 문구점 '소나무마켓' 운영자) · 인터뷰어: AI (질문) + 나 (역할 연기)
- 원칙: 미래 가정 · 의견 대신 **과거의 구체적인 사례**를 묻는다.

## 1. 겪은 일 (사실)
| # | 질문 | 답 (요약) | 읽어 낸 것 |
|---|---|---|---|
| Q1 | 최근 배송비로 고객 문의가 온 가장 최근 사례는? | 지난주 29,900원 주문 고객이 "100원 모자라서 3,000원을 냈다"며 항의, 주문 취소 | 30,000원 경계가 실제 사고 지점 |
| Q2 | 그 주문의 배송비는 어떤 금액으로 계산했나? 쿠폰·포인트는 언제 적용됐나? | 쿠폰·포인트를 뺀 실제 결제 금액 기준. 적용 전 금액으로 계산해 무료배송이 잘못 나간 적이 있다 | 입력은 '결제할 금액'(할인 후)이어야 한다 |
| Q3 | 주문 금액은 어떤 형태로 들어오나? 이상한 값이 들어온 적은? | 원 단위 정수. 지난 분기에 0원 주문과 빈 값(null)이 들어와 시스템이 멈췄다 | 0 이하 오류 · 정수가 아닌 값 오류가 둘 다 필요 |
| Q4 | 그때 멈춘 뒤 어떻게 복구했나? | 오류 메시지가 'NoneType …' 뿐이라 개발자를 불렀다 | 오류 메시지에 '무엇이 왜 잘못인지' 가 들어가야 한다 |
| Q5 | 배송비 정책은 마지막으로 언제, 왜 바뀌었나? | 3월에 무료 기준을 50,000 → 30,000원으로. 행사 때마다 바뀔 수 있다 | 기준 값은 한 곳에서 바꾸기 쉬워야 한다 |
| Q6 | 지금은 배송비를 어떻게 확인하나? | 엑셀 표를 눈으로 맞춘다. 두 번 틀렸다 | 자동으로 확인되는 사례 표가 필요 |
| Q7 | 도서산간이나 해외 주문은? | 도서산간은 3,000원 추가, 아직 수작업. 이번에는 빼고 싶다 | 이번 범위 밖 (다음 릴리스) |
| Q8 | 속도나 동시 접속 문제는? | 하루 300건, 문제된 적 없다 | 성능 요구 없음 |

## 2. 요구사항 3줄에 없던 것 (새로 알게 된 것)
1. 입력 금액은 **쿠폰 · 포인트 적용 후** 결제 금액이다 (호출하는 쪽의 책임으로 명시).
2. 정수가 아닌 값(소수 · 빈 값 · 문자열 · 불리언)은 **TypeError** 로 거절하고 메시지에 '정수' 를 쓴다.
3. 오류 메시지는 사유를 한국어로 말한다 (`주문 금액은 0보다 커야 합니다.` · `주문 금액은 정수여야 합니다.`).
4. 무료배송 기준(30,000)과 기본 배송비(3,000)는 코드 한 곳의 이름 있는 값으로 둔다 → 리팩터링 후보.

## 3. 결정할 수 없었던 것 (OQ)
- OQ-1 도서산간 추가 배송비 3,000원 — 운영자도 아직 규칙이 정리되지 않았다. 이번 Feature 에서는 구현하지 않는다 (⏸).
