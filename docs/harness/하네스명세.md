# 하네스 명세 — scripts/tdd.py (핵심 3개 명령: next · red · green)

이 문서는 Codex 에게 하네스를 만들게 할 때 건네는 **요구사항**이다. 구현이 아니라 ‘무엇을 확인하고 무엇을 거절하는가’ 를 적었다.
완성 기준은 인수 테스트 `harness_tests/test_harness_core.py` 가 모두 통과하는 것이다.

## 0. 목적과 원칙

- AI 가 ‘했다’ 고 말한 것이 아니라 **스크립트가 직접 확인한 것**만 증거로 남기고, 단계마다 커밋을 만든다.
- 파일은 하나: `scripts/tdd.py`. **표준 라이브러리만** 쓴다 (argparse · subprocess · json · re · pathlib 등).
- 사용법: `python scripts/tdd.py next` · `python scripts/tdd.py red TC-1` · `python scripts/tdd.py green TC-1`
- 성공하면 `[OK] …` 를 출력하고 종료 코드 0, 거절하면 `[STOP] 이유` 를 출력하고 **종료 코드 1**.
- 출력은 UTF-8 로 맞춘다: `sys.stdout.reconfigure(encoding="utf-8")`.

## 1. 공통 도구 (세 명령이 같이 쓴다)

| 이름 | 하는 일 |
|---|---|
| `ROOT` | 프로젝트 루트 = `scripts/tdd.py` 가 있는 폴더의 부모 |
| `run(cmd)` | 명령을 `ROOT` 에서 실행해 (종료 코드, stdout + stderr) 를 돌려준다. 명령의 `python` 은 지금 쓰는 인터프리터(`sys.executable`)로 바꾼다. 환경 변수 `PYTHONUTF8=1` |
| `git(*args)` | `git` 실행. 출력에서 `warning:` 으로 시작하는 줄은 뺀다 (샌드박스가 전역 설정 파일을 못 읽어 내는 경고) |
| `die(이유)` | `[STOP] 이유` 출력 후 종료 코드 1 로 끝낸다 |
| `read_plan()` | `plan.md` 의 표 행을 읽는다. 행은 `\| 상태 \| P \| TC \| 계약 \| 유형 \| 제목 \| 입력 \| 기대 \|` 이고 상태는 `☐`(미완료) · `☑`(완료) · `⏸`(결정 대기). `plan.md` 가 없으면 `[STOP] plan.md 가 없습니다. …` |
| 증거 파일 | `logs/tdd/<TC>/evidence.json` — 읽기 `load(tc)` · 쓰기 `save(tc, ev)` |
| `commit(제목, ev, 경로들)` | ① `git add -A -- 경로들` (실패하면 `[STOP] git add 실패`) ② 스테이징된 변경이 없으면 `None` 을 돌려주고 커밋하지 않는다 ③ 있으면 `git commit -F -` 로 커밋: 제목 + 빈 줄 + 본문(`Feature: F-01` · `Contract: CT-1 (AC, P1)` · `Evidence: …`) ④ 짧은 해시를 돌려준다 |
| `ensure_git_writable()` | `.git` 에 파일을 쓸 수 있는지 시험한다. 못 쓰면 `[STOP] .git 에 쓸 수 없습니다 …` (샌드박스 안에서 실행된 것 — 커밋이 조용히 건너뛰어지지 않게) |
| `guard_harness()` | `ensure_git_writable()` 을 부른 뒤 `git status --porcelain -- scripts AGENTS.md .codex` 가 비어 있지 않으면 `[STOP] 하네스 · 규칙 파일이 커밋된 상태와 다릅니다. …` (AI 가 하네스를 고쳐 통과시키지 못하게). `red` · `green` 이 증거를 읽기 전에 부른다 |

### 증거 파일 `evidence.json` 의 내용

`next` 가 만든다: `tc` · `p`(숫자) · `label`(계약 칸) · `kind`(유형) · `title`(제목) · `feature`(예 F-01) · `branch` · `base`(그때의 HEAD 짧은 해시) · `started`
`red` 가 더한다: `red` = `{ status("RED" | "NO-RED"), exit_code, summary, commit }`
`green` 이 더한다: `green` = `{ exit_code, summary, commit }`

## 2. `next` — 이번 루프에서 할 TC 하나를 고른다

위에서부터 차례로 확인하고, 하나라도 어긋나면 거절한다.

| # | 확인 | 어긋나면 |
|---|---|---|
| 1 | `pytest` 와 `hypothesis` 를 import 할 수 있다 | `[STOP] <오류> — 가상환경(.venv)을 활성화한 터미널에서 codex 를 시작했는지 확인하세요.` |
| 2 | `.git` 에 쓸 수 있다 (`ensure_git_writable`) | 공통 도구의 메시지 |
| 3 | 브랜치 이름이 `feature/F-<숫자>-…` 모양이다 | `[STOP] 현재 브랜치 '<이름>' 는 Feature 브랜치가 아닙니다. 예: git switch -c feature/F-01-shipping-fee` |
| 4 | `git status --porcelain` 이 비어 있다 | `[STOP] 커밋되지 않은 변경이 있습니다. 이전 루프를 report 로 끝내거나 정리한 뒤 다시 go 하세요:` + 변경 목록 |

통과하면: `plan.md` 에서 **첫 번째 ☐ 행**을 고른다 (☑ · ⏸ 는 건너뛴다).

- ☐ 가 하나도 없으면 `[끝] 미완료(☐) TC 가 없습니다. …` 를 출력하고 **종료 코드 0** 으로 끝난다.
- 있으면 `evidence.json` 을 새로 쓰고 다음을 출력한다 (종료 코드 0):

```text
[NEXT] TC-1 · P1 · CT-1 · AC · 기본 배송비 3,000원
  입력      : 10,000원 · 1 ~ 29,999원
  기대 결과 : 배송비 3,000원
  남은 ☐ 5개 · ⏸ 1개 · 브랜치 feature/F-01-shipping-fee · 기준 커밋 9d96be3
```

`next` 는 파일을 고치지도 커밋하지도 않는다 (`logs/` 는 `.gitignore` 에 있다).

## 3. `red TC-n` — 새 테스트가 ‘의도한 이유’ 로 실패하는지 확인하고 커밋한다

| # | 확인 | 어긋나면 |
|---|---|---|
| 1 | `guard_harness()` | 공통 도구의 메시지 |
| 2 | `logs/tdd/<TC>/evidence.json` 이 있다 | `[STOP] TC-1 증거 파일이 없습니다. 먼저 `python scripts/tdd.py next` 를 실행하세요.` |
| 3 | `tests/` 아래에 **새로 만들거나 고친 `.py` 파일**이 있다 (`git status --porcelain --untracked-files=all -- tests`) | `[STOP] 새로 만들거나 고친 테스트 파일(tests/*.py)이 없습니다. 먼저 RED 테스트를 작성하세요.` |
| 4 | 그 파일들만 `python -m pytest -q <파일들>` 로 실행한다. 종료 코드가 2(수집 오류) 나 5(테스트 없음)이거나 출력에 `error during collection` 이 있으면 RED 가 아니다 | `[STOP] RED 가 아닙니다 — 수집 오류이거나 실행된 테스트가 없습니다 (종료 코드 N). 먼저 해결하세요.` + 출력 끝 14줄 |

통과하면: 종료 코드 1(테스트 실패) = **RED**, 0(처음부터 통과) = **NO-RED**.
증거에 `red` 를 기록하고, `tests/` 를 커밋한다. 제목은 `test(<TC>): <제목> [RED]` (NO-RED 면 `[NO-RED]`).
출력: `[OK] RED — 종료 코드 1 · <pytest 요약> · 커밋 <해시>` (NO-RED 면 `[OK] NO-RED — 종료 코드 0 · …` 에 `[주의] 새 테스트가 처음부터 통과했습니다. …` 한 줄을 덧붙인다).
RED 와 NO-RED 모두 **하네스의 종료 코드는 0** 이다 — 다만 NO-RED 라는 사실이 증거와 커밋 제목에 남는다.

## 4. `green TC-n` — 구현이 테스트를 통과시켰는지 확인하고 커밋한다

| # | 확인 | 어긋나면 |
|---|---|---|
| 1 | `guard_harness()` · 증거 파일 | 위와 같음 |
| 2 | 증거에 `red` 가 있다 | `[STOP] RED 증거가 없습니다. red 단계를 먼저 하세요.` |
| 3 | RED 커밋 이후 `tests/` 가 바뀌지 않았다 (`git diff --name-only <RED 커밋> -- tests`, RED 커밋이 없으면 `base` 와 비교) | `[STOP] RED 커밋 이후 tests/ 가 바뀌었습니다. 통과시키려고 테스트를 고치지 않습니다:` + 파일 목록 |
| 4 | `python -m pytest -q -m "not golden"` 이 모두 통과한다 (종료 코드 0) | `[STOP] 단위 테스트 전체가 통과하지 않았습니다 (종료 코드 N).` + 출력 끝 14줄 |

통과하면 증거에 `green` 을 기록하고 변경 전체(`.`)를 커밋한다. 제목은 `feat(<TC>): <제목> [GREEN]`.
출력: `[OK] GREEN — <pytest 요약> · 커밋 <해시>` (바뀐 파일이 없어 커밋이 없으면 `커밋 (구현 변경 없음)`).

## 5. `golden TC-n [--approve]` — 동작을 사람이 승인한 골든 마스터로 남긴다

| # | 확인 | 어긋나면 |
|---|---|---|
| 1 | `guard_harness()` · 증거 파일 · 증거에 `green` 이 있다 | `[STOP] GREEN 증거가 없습니다. green 단계를 먼저 하세요.` |
| 2 | `golden_master.check_approved()` 로 기존 승인 행이 지금 동작과 같은지 확인한다 | `[STOP] 이미 승인한 동작이 바뀌었습니다 (회귀). 구현을 되돌리세요:` + 변경 목록 |
| 3 | 계약의 미승인 동작 행을 제안한다. `--approve` 가 없으면 승인 파일을 고치지 않는다 | `[승인 대기] 사용자의 '승인' 답을 받은 뒤에만 --approve 로 다시 실행합니다. 지금은 멈춥니다.` 를 출력하고 종료 코드 3 |
| 4 | `--approve` 면 제안 행을 `tests/golden/approved.txt` 에 추가하고 `python -m pytest -q -m golden` 을 실행한다 | `[STOP] 승인한 행이 골든 테스트를 통과하지 못했습니다.` + 출력 끝 14줄 |

통과하면: `--approve` 전에는 증거에 `golden = { status: "승인 대기", rows, proposal }` 을 기록한다. `--approve` 후에는 `status: "승인"` · `rows` · `proposal` · `summary` · `commit` 을 기록하고 `tests/golden/` 을 `test(golden): <계약> 동작 <N>행 승인 [APPROVED]` 로 커밋한다. 출력은 `[OK] 승인 <N>행 · <pytest 요약> · 커밋 <해시>`.

제안할 새 행이 없으면 골든 테스트를 실행하고 `status: "새 행 없음"` · `rows: 0` · `summary` 를 기록한다. `[OK] <계약> 는 새로 승인할 행이 없습니다. 기존 승인 행은 그대로입니다 (<pytest 요약>).` 를 출력하며 파일을 고치거나 커밋하지 않는다.

## 6. 만들지 않는 것 (이 명세 밖)

`smell` · `plan-check` · `refactor` · `regress` · `probe` · `report` 는 같은 패턴(확인 → 증거 → 커밋)으로 이어서 만드는 명령이다. 오늘은 제공본으로 대신한다.
